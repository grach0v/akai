# assets

Everything the nodes need to know about a robot and its cell, as files: one
directory per robot under `assets/<vendor>/<robot>/`. Meshes and textures are in
Git LFS (`.gitattributes`). `universal_robots/ur10e/` is the worked example of
everything below.

```
assets/<vendor>/<robot>/
  meshes/          # the MJCF's meshes (Git LFS)
  schemas/         # the MJCF: the simulation (generated by a script here, sources in src/)
  urdf/            # the URDF and its meshes: the kinematics (generated by a script here)
  scenes/          # scene files: the cell's files and the MJCF's parts, for the nodes
  calibration/     # camera calibration, one file per cell
```

Who reads what. Every node names these files in its own config, or takes them
from a scene file instead (its `SCENE` / `MODE__SCENE`), never both ways:

| file | read by |
| --- | --- |
| MJCF (`schemas/`) | the `mujoco` node (`MODEL`, with its `PARTS`) |
| URDF (`urdf/`) | the `rerun` node (`MODE__ROBOT_URDF`), the `web_controller` node (`MODE__URDF`) |
| calibration (`calibration/`) | the `rerun` node (`MODE__CALIBRATION`), the MJCF generator |
| scene file (`scenes/`) | any of them, in place of the above |

Two descriptions of one robot: the MJCF is the simulation, the URDF is the
kinematics, and every message uses the URDF's joint names and units. The sim's
parts map the MJCF onto them.

## The MJCF

The `mujoco` node needs from it:

1. every joint of every part, and an actuator per joint (a position servo, so a
   joint target is its `ctrl`), all named;
2. a keyframe named `home`: the sim starts there;
3. cameras by name, and an offscreen buffer (`<visual><global offwidth
   offheight>`) at least as large as the images rendered.

Start from [MuJoCo Menagerie](https://github.com/google-deepmind/mujoco_menagerie)
or the vendor's model: copy its XMLs and license into `schemas/src/` and its
meshes into `meshes/`. Compose the cell with a script on
[`MjSpec`](https://mujoco.readthedocs.io/en/stable/programming/modeledit.html)
(`schemas/build_*.py`, a [uv script](https://docs.astral.sh/uv/guides/scripts/)
declaring its own dependencies): attach the gripper, name the actuators, add the table,
lights and cameras (from the calibration file), and write the `home` keyframe.
Commit the script and the MJCF it writes. Look at the result, its joint,
actuator and camera names included, in MuJoCo's viewer:

```sh
nodes/mujoco/.venv/bin/python -m mujoco.viewer --mjcf=assets/<vendor>/<robot>/schemas/<model>.xml
```

## The URDF

Get it with [`robot_descriptions`](https://github.com/robot-descriptions/robot_descriptions.py),
which fetches the vendors' own descriptions, and expand xacro where needed
(`xacrodoc`). Keep its meshes in `urdf/meshes/` with relative paths, as GLB or
STL (rerun does not read Collada). A script (`urdf/build_urdf.py`) does all of
this, so the URDF can be regenerated.

## The scene file

YAML, written by hand: one file naming everything the nodes need to know about a
cell, so a dataflow names the cell once instead of every file in every node. It
is a convenience: each node can be given the same through its own config. Every
section is optional, paths are relative to the file, and every node reads it
through the `akai-scene` package ([`libs/scene`](../libs/scene)), which defines
and validates the format.

```yaml
urdf: ../urdf/ur10e_2f85.urdf              # the kinematics
calibration: ../calibration/tabletop.yaml  # the cameras
mujoco:                                    # the simulation
  model: ../schemas/ur10e_2f85.xml
  parts:                                   # by name; part <p> goes out as <p>_joint_state
    arm:
      joints: [shoulder_pan_joint, shoulder_lift_joint, elbow_joint,
               wrist_1_joint, wrist_2_joint, wrist_3_joint]
    gripper:
      joints: [2f85/right_driver_joint]
      actuators: [gripper]
      urdf_joints: [finger_joint]
      urdf_scale: [0.90625]
```

| key | meaning |
| --- | --- |
| `urdf` | the robot's URDF |
| `calibration` | the cell's calibration file |
| `mujoco.model` | the MJCF |
| `mujoco.parts.<p>.joints` | MJCF joint names, in the order the part's vectors list them (required per part) |
| `mujoco.parts.<p>.actuators` | MJCF actuators driving them, one per joint; default: named after the joints |
| `mujoco.parts.<p>.urdf_joints` | the joints' URDF names; default: the MJCF names |
| `mujoco.parts.<p>.urdf_scale` | URDF value = MJCF value × scale, per joint; default: 1 |

The `mujoco` node takes `parts` in the same format through its own config
(`PARTS`, as JSON). To fill in a part's URDF mapping, compare each MJCF joint
with its URDF counterpart: same name, zero and direction need nothing; a
different name needs `urdf_joints`; a different unit or range needs
`urdf_scale`, e.g. the ratio of the two joint ranges. Unknown keys, a list of the
wrong length, a file that does not exist and a name the MJCF does not have are
errors. Check a scene file, its parts against the MJCF included:

```sh
nodes/mujoco/.venv/bin/python nodes/mujoco/src/scene.py assets/<vendor>/<robot>/scenes/<scene>.yaml
```

## The calibration file

YAML, one file per cell, the output of calibrating its cameras (for a simulated
cell, its design, from which the MJCF generator builds the cameras). Per camera:

```yaml
cameras:
  cam_wrist:
    frame: tool0                 # the URDF frame the camera is rigidly mounted on
    extrinsics: [0.0, -0.08, 0.0408, -0.122183, 0.0, 0.0, 0.992508]
    intrinsics: [312.7741, 312.7741, 320.0, 240.0]
    width: 640
    height: 480
```

| key | meaning |
| --- | --- |
| `frame` | the URDF frame (link) the camera is mounted on |
| `extrinsics` | `[x, y, z, qx, qy, qz, qw]`: the camera's optical frame (x right, y down, z forward) in `frame`, metres and a unit quaternion |
| `intrinsics` | `[fx, fy, cx, cy]`: pinhole intrinsics in pixels |
| `width`, `height` | the image size the intrinsics are for |
