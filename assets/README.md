# assets

Everything the nodes need to know about robots and the cells they work in, as
files. Meshes and textures are in Git LFS (`.gitattributes`). The UR10e and its
tabletop cell are the worked example of everything below.

```
assets/
  <vendor>/<robot>/   # one robot, alone: its URDF and MJCF (e.g. universal_robots/ur10e)
    meshes/           # the MJCF's meshes (Git LFS)
    schemas/          # the MJCF: the simulation (generated by a script here, sources in src/)
    urdf/             # the URDF and its meshes: the kinematics (generated by a script here)
  props/<prop>/       # reusable things a cell holds (table, floor, ...): one small URDF each
  cells/
    build_cell.py     # composes a cell's robots and props into its URDF and MJCF
    <cell>/           # one cell (e.g. ur10e_tabletop)
      scene.yaml      # what the cell is made of, and what the nodes load
      calibration.yaml
      <cell>.urdf     # built: the cell's kinematics, robots and props
      <cell>.xml      # built: the cell's simulation, with lights, cameras and a home keyframe
```

A robot does not know where it stands: a cell does. Every cell has its own
`world` frame, at floor level, and places each robot and prop in it, so one
robot works in any cell, and a cell can hold two arms or an arm on a mobile
base.

Who reads what. Every node names these files in its own config, or takes them
from the cell's scene file instead (its `SCENE` / `MODE__SCENE`), never both ways:

| file | read by |
| --- | --- |
| the cell's MJCF | the `mujoco` node (`MODEL`, with its `PARTS`) |
| the cell's URDF | the `rerun` node (`MODE__ROBOT_URDF`), the `web_controller` node (`MODE__URDF`), the `pink` node (`URDF`) |
| calibration | the `rerun` node (`MODE__CALIBRATION`), the cell builder |
| scene file | any of them, in place of the above; the cell builder |

Two descriptions of one cell: the MJCF is the simulation, the URDF is the
kinematics, and every message uses the URDF's joint names and units. The sim's
parts map the MJCF onto them.

## A robot's MJCF

Start from [MuJoCo Menagerie](https://github.com/google-deepmind/mujoco_menagerie)
or the vendor's model: copy its XMLs and license into `schemas/src/` and its
meshes into `meshes/`. Compose the robot with a script on
[`MjSpec`](https://mujoco.readthedocs.io/en/stable/programming/modeledit.html)
(`schemas/build_*.py`, a [uv script](https://docs.astral.sh/uv/guides/scripts/)
declaring its own dependencies) and commit the script and the MJCF it writes. A cell
needs from it:

1. an actuator per joint of every part (a position servo, so a joint target is
   its `ctrl`), named after the URDF joint it drives, its ctrl and length in that
   joint's units (the 2F-85's is geared from its driver angle to the URDF's
   `finger_joint`);
2. a site named after each URDF frame the cell uses: the URDF's root link (the
   cell places the robot by it) and every frame a camera is mounted on.

## A robot's URDF

Get it with [`robot_descriptions`](https://github.com/robot-descriptions/robot_descriptions.py),
which fetches the vendors' own descriptions, and expand xacro where needed
(`xacrodoc`). Root it at the robot's base link (no `world`: the cell has it). Keep
its meshes in `urdf/meshes/` with relative paths, as GLB or STL (rerun does not
read Collada). A script (`urdf/build_urdf.py`) does all of this, so the URDF can
be regenerated.

## Props

A prop is one URDF link made of primitive shapes (boxes, cylinders, spheres),
with a visual and a collision shape each and colours as materials:
`props/table/table.urdf`, `props/floor/floor.urdf`. Put its frame where placing
it is natural (the table's is the centre of its footprint on the floor). MuJoCo
reads it from the URDF too, so one file serves both.

## A cell

A directory under `cells/` with a scene file and a calibration file. The scene
file's `robots` and `props` place each one in the cell's `world`, and the cell
builder composes them into the cell's URDF and MJCF, which are committed:

```sh
uv run assets/cells/build_cell.py --scene assets/cells/<cell>/scene.yaml
```

* The URDF: a `world` link, the robot's URDF and every prop's link, each fixed to
  `world` at its pose by a `<name>_mount` joint.
* The MJCF: the robot's MJCF, placed so its root-link site is at its pose; the
  props; a light; the calibration's cameras, each on `world` or on the robot's
  site for its frame, with its exact pinhole intrinsics; an offscreen buffer for
  the renders; and a `home` keyframe from the scene, every servo's ctrl at its
  joint so the sim starts at rest.

One robot per cell for now: a second needs its names prefixed in both files.
Look at the result, its joint, actuator and camera names included, in MuJoCo's
viewer:

```sh
nodes/mujoco/.venv/bin/python -m mujoco.viewer --mjcf=assets/cells/<cell>/<cell>.xml
```

## The scene file

YAML, written by hand, one per cell: what the cell is made of, for the cell
builder, and what the nodes need to know about it, so a dataflow names the cell
once instead of every file in every node. For the nodes it is a convenience:
each can be given the same through its own config. Paths are relative to the
file, and everything reads it through the `akai_scene` package
([`libs/akai_scene`](../libs/akai_scene)), which defines and validates the format.

```yaml
robots:
  ur10e:
    urdf: ../../universal_robots/ur10e/urdf/ur10e_2f85.urdf
    mjcf: ../../universal_robots/ur10e/schemas/ur10e_2f85.xml
    pose: [0, 0, 0.75, 0, 0, 1, 0]   # on the table top
    home: {shoulder_pan_joint: 2.8706, ...}
props:
  floor: {urdf: ../../props/floor/floor.urdf, pose: [0, 0, 0, 0, 0, 0, 1]}
  table: {urdf: ../../props/table/table.urdf, pose: [0.35, 0, 0, 0, 0, 0, 1]}

urdf: ur10e_tabletop.urdf            # built
calibration: calibration.yaml
mujoco:
  model: ur10e_tabletop.xml          # built
  parts:                             # by name; part <p> goes out as <p>_joint_state
    arm: [shoulder_pan_joint, shoulder_lift_joint, elbow_joint,
          wrist_1_joint, wrist_2_joint, wrist_3_joint]
    gripper: [finger_joint]
```

| key | meaning |
| --- | --- |
| `robots.<r>.urdf`, `.mjcf` | the robot's URDF and MJCF |
| `robots.<r>.pose` | `[x, y, z, qx, qy, qz, qw]`: where its URDF root link is in `world` |
| `robots.<r>.home` | the `home` keyframe: actuator (URDF joint) -> position; others start at zero |
| `props.<p>.urdf`, `.pose` | the prop, and where its link is in `world` |
| `urdf` | the cell's URDF |
| `calibration` | the cell's calibration file |
| `mujoco.model` | the cell's MJCF |
| `mujoco.parts.<p>` | the part's MJCF actuators, in the order its vectors list them |

The MJCF's actuators are the robot's interface, named and scaled like the URDF
joints, so a part needs no mapping. The `mujoco` node takes `parts` in the same
format through its own config (`PARTS`, as JSON). Unknown keys and a file that
does not exist are errors when a node reads the scene file, and a name the MJCF
does not have when the sim starts.

## The calibration file

YAML, one file per cell, the output of calibrating its cameras (for a simulated
cell, its design, from which the cell builder makes the MJCF cameras). Per camera:

```yaml
cameras:
  cam_wrist:
    frame: tool0                 # the URDF frame the camera is rigidly mounted on
    extrinsics: [0.0, -0.08, 0.0408, -0.122183, 0.0, 0.0, 0.992508]
    intrinsics: [312.7741, 312.7741, 320.0, 240.0]
    width: 640
    height: 480
```

| key | meaning |
| --- | --- |
| `frame` | the URDF frame (link) the camera is mounted on: `world`, or a robot's |
| `extrinsics` | `[x, y, z, qx, qy, qz, qw]`: the camera's optical frame (x right, y down, z forward) in `frame`, metres and a unit quaternion |
| `intrinsics` | `[fx, fy, cx, cy]`: pinhole intrinsics in pixels |
| `width`, `height` | the image size the intrinsics are for |
| `depth` | optional, `true`: the camera also gives a depth image aligned to its color image (same intrinsics and size) |
